# 10.0 staging foundation
Legacy OWL STORE remains in its original tables and routes; no migration of historic data. New merchants use separate tables, session identity and scoped queries. New vendor invoices are printable, branded with business name/address snapshots, and cannot initiate payment. Offline KYC review only; no document uploads or automated KYC. No vendor EMI, terminals, products, staff or gateway yet. Public invoice links are bearer secrets; share only with intended customer. Not production ready: add rate limits, audit trail, email verification, DB row-level isolation and security review before public onboarding.

Use a disposable Neon branch and sandbox credentials. Run migrations/007_saas.sql in Neon SQL Editor or `flask --app app upgrade-saas`. Keep existing enterprise migration. Set PLATFORM_ADMIN_PASSWORD_HASH to a Werkzeug password hash generated locally: `python -c "from werkzeug.security import generate_password_hash; from getpass import getpass; print(generate_password_hash(getpass()))"`. Keep existing SECRET_KEY. Start command: `gunicorn app:app --bind 0.0.0.0:$PORT --workers 2 --threads 4`. Routes /merchant/platform, /merchant/register, /merchant/login. Run `python -m unittest discover -s tests` against disposable SQLite (test suite sets its own database). Never run tests against production. Verify legacy checkout and signed webhook in sandbox separately.
